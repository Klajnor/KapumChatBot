# 🤖 Telegram AI Bot — Qwen (Model Studio) + PostgreSQL

Telegram-бот с интеграцией **Qwen** через OpenAI-совместимый API Alibaba Cloud
Model Studio. Поддерживает текстовые диалоги, распознавание голосовых сообщений,
анализ изображений, генерацию картинок, ответы в Markdown-разметке, выбор модели,
настройку системного промпта, гостевой доступ и **guest chat mode** — вызов бота
в любом чате или группе без добавления его туда.

## ✨ Возможности

- 💬 **Чат с AI** — модели Qwen 3.8 / 3.7 и DeepSeek V4 (список настраивается в `.env`)
- 📝 **Ответы в Markdown** — жирный/курсив, код, списки, ссылки, цитаты
  (MarkdownV2 с автоматическим fallback на HTML и plain text)
- 🧪 **Формулы без LaTeX** — химия и физика автоматически переводятся в Unicode:
  `H_2SO_4` → H₂SO₄, `$E = mc^2$` → E = mc², `\alpha` → α, `10^{23}` → 10²³
  (блоки кода и `snake_case` не затрагиваются)
- ⏳ **Индикатор ожидания** — если модель отвечает дольше 5 с, бот показывает
  сообщение «жду ответа» и обновляет его раз в секунду, а перед ответом удаляет
- 🎤 **Голосовые сообщения** — бот распознаёт речь (`qwen3-asr-flash`) и отвечает
- 🖼️ **Анализ изображений** — фото обрабатывают vision-модели (отмечены 🖼️ в `/models`)
- 🎨 **Генерация картинок** — `/image <промпт>` или просто попросите «нарисуй…» —
  AI сам решит ответить текстом или картинкой
- 🔎 **Актуальный список моделей** — при запуске проверяется через `GET /models`; недоступные для аккаунта модели скрываются
- 🤖 **Выбор модели** — переключение модели командой `/models`
- ⚙️ **Системный промпт** — настройка поведения AI
- 📚 **История диалога** — контекст сохраняется в PostgreSQL **по чату**
- 🧹 **Очистка истории** — сброс контекста текущего чата (`/clear`)
- 👥 **Группы** — бот отвечает на упоминание `@username` или на reply
- 🌍 **Guest chat mode** — `@bot вопрос` в **любом** чате или группе, даже там,
  где бот не состоит (Bot API 10.0, без inline-режима)
- 🎁 **Гостевой доступ** — неавторизованные пользователи получают несколько
  бесплатных вопросов
- 👑 **Администрирование** — белый список пользователей, дневной лимит и
  статистика за 14 дней

## 🛠️ Стек технологий

- **Python 3.10+**
- **aiogram 3.x** — асинхронный фреймворк для Telegram Bot API
- **PostgreSQL** — база данных
- **SQLAlchemy 2.0 (async)** + **asyncpg** — ORM и драйвер
- **aiohttp** — HTTP-клиент
- **Qwen API** (Alibaba Cloud Model Studio, OpenAI-совместимый режим)

Используйте OpenAI-совместимый адрес Model Studio. Ключ должен быть создан в

| Китай (Beijing) | `https://dashscope.aliyuncs.com/compatible-mode/v1` |

### Модели

Список моделей для меню `/models` задаётся **в `.env`** переменной `AI_MODELS` —
код трогать не нужно. Формат записи (через запятую и/или с новой строки):

```
AI_MODELS=model-id:Отображаемое имя:vision
```

- `model-id` — идентификатор модели в API (обязательно);
- `Отображаемое имя` — текст кнопки в меню (по умолчанию равен `model-id`);
- третий параметр — `vision` (модель принимает изображения) или `novision`
  (только текст). Если флаг не указан, бот определяет vision-поддержку сам по
  идентификатору (семейства Qwen-VL / Omni / OCR и Qwen3.5+ `max|plus|flash`).

Пример из `.env`:

```
AI_MODELS=qwen3.8-max:Qwen 3.8 Max:vision,qwen3.8-flash:Qwen 3.8 Flash:vision,qwen3.8-omni-flash:Qwen 3.8 Omni Flash:vision,qwen3.5-ocr:Qwen 3.5 OCR:vision,deepseek-v4-pro-0813:DeepSeek V4 Pro:novision,deepseek-v4.1-flash-1017:DeepSeek V4.1 Flash:vision
```

Если `AI_MODELS` не задана, используется встроенный список
`DEFAULT_AI_MODELS` из `bot/config.py`.

При запуске бот запрашивает `GET {AI_BASE_URL}/models` и **скрывает** из меню
модели, недоступные для вашего аккаунта/региона (если запрос не удался —
показывается весь список). Vision-модели помечаются значком 🖼️, а выбор
недоступной модели отклоняется.

Чтобы добавить или убрать модель — просто отредактируйте `AI_MODELS` и
перезапустите бота.

### Голосовые сообщения и картинки

- **Голос** → скачивается, отправляется в `ASR_MODEL` (`qwen3-asr-flash`,
  принимает OGG/Opus из Telegram напрямую, до 10 МБ / 5 мин), бот показывает
  распознанный текст и отвечает на него как на обычное сообщение.
- **Картинки** → модель получает инструмент `generate_image` и сама решает,
  ответить текстом или сгенерировать изображение (например, «нарисуй кота»).
  Также доступна команда `/image <промпт>`.

Генерация использует нативный API DashScope
(`{AI_BASE_URL → /api/v1}/services/aigc/multimodal-generation/generation`),
результат скачивается и отправляется в чат. В guest-режиме картинка отдаётся
сразу по URL (`InlineQueryResultPhoto`).

Скачивание идёт **отдельной сессией без заголовка `Authorization`**: API
возвращает подписанную ссылку на Alibaba Cloud OSS, а такие URL отдают `403`,
если в запросе есть ещё и токен («only one auth mechanism allowed»). Первой
пробой идёт анонимный запрос, второй — с токеном; ошибка логируется вместе с
телом ответа (подпись в лог не попадает). Если байты всё же не удалось получить,
бот просит Telegram скачать картинку по URL сам, а при неудаче отправляет
кликабельную ссылку (живёт ~24 часа) вместо сообщения об ошибке.

### Форматирование ответов (Markdown)

Ответы модели приходят в разметке. `PARSE_MODE` задаёт формат:

| Значение | Что делает |
|----------|-----------|
| `markdown` | MarkdownV2 (по умолчанию) |
| `html` | HTML-разметка Telegram |
| `plain` | текст без разметки |

Markdown модели (`**жирный**`, `*курсив*`, `` `код` ``, блоки кода, списки,
заголовки, ссылки, цитаты, `~~зачёркнутый~~`) преобразуется в корректный
MarkdownV2 с экранированием всех спецсимволов — `bot/services/markdown.py`.
`snake_case` и URL не ломаются. Длинные ответы режутся по границам блоков с
учётом уже отрендеренной длины.

Если Telegram всё же отклоняет разметку, сообщение автоматически
переотправляется как HTML, а затем как plain text — ответ не теряется.

### Формулы и научные обозначения

В Telegram **нет** рендеринга LaTeX и нет форматирования подстрочных/надстрочных
индексов (в MarkdownV2 и HTML нет `sub`/`sup`), а модели любят отвечать именно
так. Поэтому ответ прогоняется через `bot/services/science.py` и переводится в
Unicode-символы, которые выглядят одинаково на любом клиенте:

| Модель прислала | Пользователь видит |
|-----------------|--------------------|
| `H_2SO_4`, `CO_2`, `Ca(OH)_2` | H₂SO₄, CO₂, Ca(OH)₂ |
| `\ce{2H2 + O2 -> 2H2O}` | 2H₂ + O₂ → 2H₂O |
| `$E = mc^2$`, `m/s^2` | E = mc², m/s² |
| `6.022 \times 10^{23}` | 6.022 × 10²³ |
| `\frac{s}{t}`, `\sqrt{2}` | s/t, √2 |
| `\alpha`, `\Delta G`, `\Omega` | α, ΔG, Ω |
| `25 ^\circ C` | 25 °C |
| `\leq`, `\neq`, `\pm`, `\approx` | ≤, ≠, ±, ≈ |
| `A -> B`, `a <= b` | A → B, a ≤ b |
| `x_{max}`, `x_1`, `\vec{F}` | xₘₐₓ, x₁, F⃗ |

Что **не** меняется:

- содержимое блоков кода ` ``` ` и инлайн-кода `` ` ``;
- идентификаторы `user_name`, `MAX_VALUE`, `item_1`, `x86_64` (подстрочный
  индекс ставится только там, токен разбирается как последовательность
  химических элементов — используется таблица Менделеева);
- цены `$5 и $10`, пути `C:\Users\test`, неизвестные `\команды`.

Дополнительно модели через системный промпт объясняется, что отвечать нужно
сразу в Unicode и без LaTeX/таблиц (`ENABLE_STYLE_HINT`, текст — `STYLE_HINT`),
поэтому нормализация обычно лишь подстраховка.

Ограничение Unicode: заглавных подстрочных букв не существует, поэтому `N_A`
(постоянная Авогадро) и `K_eq` остаются как есть, а символы вроде `ₓ ᵢ ₘ ₐ`
поддерживаются не всеми шрифтами. Если нужна настоящая математическая вёрстка,
формулу придётся отдавать картинкой (см. ниже «Что можно улучшить»).

Отключается целиком: `NORMALIZE_FORMULAS=false`.

### Индикатор ожидания («жду ответа»)

Запросы к модели (особенно с инструментами, анализом фото и генерацией картинок)
могут идти десятки секунд. Чтобы это не выглядело зависанием:

1. `PROGRESS_DELAY` секунд (по умолчанию 5) бот ждёт молча;
2. если ответ ещё не пришёл — отправляет сообщение
   `⠹ Жду ответа нейросети… 6 с`;
3. каждые `PROGRESS_INTERVAL` секунд (по умолчанию 1) **редактирует** его,
   обновляя спиннер и счётчик секунд, и параллельно освежает статус «печатает…»;
4. как только ответ готов — сообщение **удаляется**, и следом уходит сам ответ.

Если модель ответила быстрее порога, лишнее сообщение не появляется вообще.
Все вызовы Telegram здесь best-effort: ошибки отправки/редактирования/удаления
логируются и никогда не ломают ответ. Текст настраивается через `PROGRESS_TEXT`
(плейсхолдеры `{spinner}` и `{seconds}`), в группах сообщение отправляется как
reply на вопрос пользователя.

В guest chat mode индикатор не используется: там разрешён ровно один ответ
(`answerGuestQuery`), отдельное сообщение отправить нельзя.

## 🌍 Guest chat mode — вызов бота в любом чате

Используется **Guest Mode** из Bot API 10.0 (не inline-режим). Бот получает
отдельный апдейт `guest_message`, когда его упоминают в **любом** чате — группе
или личной переписке с другим человеком, — даже если он туда не добавлен, и
отвечает **от своего имени** прямо в этот чат через `answerGuestQuery`.

**Как включить:**

1. Откройте [@BotFather](https://t.me/BotFather) → Mini App → ваш бот →
   **Bot Settings** → включите **Guest Mode**.
2. В любом чате упомяните бота: `@ваш_бот вопрос` (или ответьте reply на его
   сообщение). Можно упомянуть до 3 guest-ботов в одном сообщении.

**Что умеет guest-режим в этом боте:**

- 💬 текстовый вопрос → ответ с Markdown-разметкой;
- 🎤 голосовое сообщение → распознаётся (`qwen3-asr-flash`) и обрабатывается
  как обычный запрос;
- 🖼️ фото в сообщении или в сообщении, на которое отвечают, → анализ
  vision-моделью;
- 🎨 просьба «нарисуй …» → бот отвечает **картинкой** (URL сгенерированного
  изображения передаётся в `InlineQueryResultPhoto`).

**Ограничения Telegram:** guest-бот не получает историю чата и список
участников, видит только сообщение-вызов (и сообщение, на которое оно
отвечает), и может дать **ровно один ответ** на вызов. Поэтому вся работа
ограничена таймаутом `GUEST_TIMEOUT`, а при ошибке разметки ответ
автоматически повторяется обычным текстом. Свою историю бот ведёт сам — по
`chat_id` вызывающего чата, так что контекст между вызовами сохраняется.

> Inline-режим в боте **отключён и не используется**.

## 👥 Работа в группах

Чтобы бот отвечал в группах:

1. В @BotFather: **Bot Settings → Group Privacy → Turn off** (иначе бот видит
   только команды и reply).
2. Добавьте бота в группу.
3. Упоминайте его (`@ваш_бот ...`) или отвечайте (reply) на его сообщение.

История диалога хранится отдельно для каждого чата.

## 🔭 Что можно улучшить

- **Настоящая математическая вёрстка.** Unicode покрывает простые формулы, но не
  дроби в две строки, интегралы с пределами, матрицы и многоярусные индексы.
  Вариант — определять «сложную» математику в ответе и отдавать её картинкой:
  рендерить LaTeX локально (`matplotlib.mathtext`, без сети) или через
  KaTeX/MathJax, отправлять PNG и дублировать исходник под катом. Цена:
  зависимость и ~100–300 мс на формулу.
- **Стриминг ответа.** Сейчас сообщение приходит целиком; с `stream=true` можно
  редактировать одно сообщение по мере генерации (индикатор ожидания при этом
  становится не нужен).
- **Таблицы.** Telegram их не поддерживает — сейчас модель просят заменять их
  списками; можно автоматически превращать Markdown-таблицу в картинку или в
  выровненный моноширинный блок.
- **Webhook вместо long polling** для продакшена (меньше задержки, нужен HTTPS).

## 🔄 Переход с OpenRouter

Старый клиент OpenRouter заменён на универсальный OpenAI-совместимый клиент
`bot/services/ai_client.py`. Достаточно указать ключ и `AI_BASE_URL` Qwen —
код, форматы запросов и ответов совпадают.
