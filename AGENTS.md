# AGENTS.md

This file provides guidance to AI coding agents (Codex, Cursor, Copilot, Claude Code, etc.) when working with code in this repository.

## Что это

Telegram-бот на **aiogram 3.x (≥ 3.29, Python 3.12+)** поверх OpenAI-совместимого API Qwen (Alibaba Model Studio) и других провайдеров. БД — **только SQLite** (`sqlite+aiosqlite`); PostgreSQL и другие СУБД — возможное будущее направление, сейчас не поддерживаются (исторические ветки диалектов в коде остаются заделом). Документация, README, CHANGELOG и комментарии — на русском; пользовательские сообщения бота — на английском; промпты модели по умолчанию — на русском.

## Команды

```bash
pip install -r requirements.txt
pip install pytest pytest-asyncio ruff   # dev-зависимости (в requirements.txt их нет)
cp .env.example .env.linux             # Linux; на Windows: copy .env.example .env.windows

python -m bot.main                       # запуск бота (так же в chat_bot.service)
python scripts/project_stats.py --write   # обновить PROJECT_STATS.md (то же делает pre-commit)

ruff check bot/ tests/                   # линт (ruff.toml: target py312)
pytest tests/ -v                         # все тесты
pytest tests/test_samo_helper.py -q      # рабочий модуль Redmine/YouGile
pytest tests/test_regressions.py -v      # один файл
pytest tests/test_regressions.py::RegressionTests::test_name -v   # один тест
```

- Тесты — в основном `unittest.IsolatedAsyncioTestCase` (запускаются через pytest). Разброс — `test_regressions.py` (регрессии), `test_database.py` (in-memory SQLite, без моков), `test_audit_fixes.py` (безопасность). Telegram-объекты подменяются `SimpleNamespace` / `unittest.mock`.
- `ffmpeg` нужен для голосовых (не pip-пакет); `ENABLE_VOICE=false` отключает. На Windows зонеinfo нужен пакет `tzdata` (REMINDER_TIMEZONE).
- `scripts/check_search.py --query "..." [--ask]` — диагностика веб-поиска; `check_telegraph.py`, `test_ws_asr.py` — отладка Telegraph и ASR; `clean_pycache.*` — очистка кэша; `restart.sh` — перезапуск сервера (`/opt/KapumChatBot`, systemd; `--no-follow` без `journalctl -f`). `scripts/update.sh` + `update_support.py` + `kapum-update.timer` — обновление бота и кода `/opt/brain` (раздельные read-only deploy-ключи, только fast-forward, root-owned код/venv, снимки окружений для отката, MCP handshake от brain, состояние `/var/lib/kapum-update`). Заметки, SQLite и установленные systemd-юниты не откатываются/не заменяются. Скрипта миграции PostgreSQL → SQLite больше нет: поддерживается только SQLite.
- Автообновление всегда возвращает ранее активный/включённый `brain-pull.timer`, даже при неполном откате; disabled/inactive не включает. Работающий `brain-pull.service` откладывает обновление мозга до следующей проверки без остановки таймера. В уведомлении об ошибке — этап/код, безопасная причина, результат отката и состояния служб; сырой stderr/исходники/секреты в Telegram не пересылать.

## Конвенции

- `from __future__ import annotations` в каждом модуле, type hints и docstrings на публичном API.
- `# noqa: BLE001` помечает намеренные широкие `except` вокруг вызовов Telegram, которые не должны ломать ответ.
- Новый параметр конфигурации → добавить в `bot/config.py` (Config dataclass), `.env.example` и таблицу в README. Их уже >100 — переменную легко добавить в одну из них и забыть про остальные.
- Коммиты на русском, тема в subject (история использует и префиксы области — `chat:`, `db:`, `docs:` — и стиль `Тема: описание`, напр. «Саммари: …»). Каждую фичу коммитить с подробным описанием в теле; добавлять запись в `CHANGELOG.md` — датированный раздел в самом верху «История по коммитам» + развернутая заметка ниже в «Подробные заметки».
- `CLAUDE.md` — зеркальная копия этого файла: менять синхронно.
- `PROJECT_STATS.md` пересчитывается `scripts/project_stats.py`; хук `.githooks/pre-commit` обновляет его перед каждым коммитом. После клонирования включить: `git config core.hooksPath .githooks`.

## Архитектура

Точка входа — `bot/main.py`: регистрирует роутеры, глобальный обработчик ошибок, запускает фоновые задачи (`_album_cleanup`, `reminder_scheduler_loop`, `digest_scheduler_loop`, health-сервер, MCP). **Порядок `dp.include_router` важен**: `digest.router` стоит первым (только наблюдает посты каналов/групп), затем командные роутеры, последним catch-all `chat.router`; `guest.router` подключается только при `ENABLE_GUEST_MODE`. Роутеров больше, чем сервисов, — перечислены в `main.py` (start, help, models, image, prompt, reminders, export, clear, stats, menu, admin, admin_panel). `menu.router` (кнопки постоянной reply-клавиатуры `keyboards/reply.py`, диалоги Image/New reminder на FSM) должен стоять до `admin_panel` и `chat`: нажатие кнопки приходит как обычный текст. `samo_helper` подключается после `tasks.router` и до `admin_panel`/`guest`/`chat`; при ошибке его настроек `_setup_samo_helper()` логирует причину и оставляет Kapum работать без модуля.

Слои:
- `bot/bot.py` — инициализация Bot/Dispatcher и хелперы идентичности бота.
- `bot/handlers/` — Telegram-обработчики. `chat.py` (~3000 строк) — ядро: текст/голос/фото/документы/альбомы, ссылки, tool-loop (поиск, картинки, стикеры, MCP), стриминг (`_StreamPrinter`), доставка ответа (`deliver_answer`), callback-и «спросить другую модель» и выбора способа улучшения фото. `guest.py` — guest chat mode (inline-запрос → ровно один `answerGuestQuery`: индикатора и поиска нет, но чтение второго мозга доступно тем же ограниченным tool-loop).
- `bot/services/` — бизнес-логика. `ai_client.py` — единый `AIClient` (чат, SSE-стриминг, vision, ASR по WebSocket, генерация картинок через нативный DashScope API, замер времени/токенов, fallback-цепочка моделей). `user_service.py` + `access.py` + `limits.py` — уровни доступа (guest → user → admin → owner из `OWNER_IDS`), дневные и персональные лимиты, атомарное списание квоты с возвратом при отказе. `documents.py` — извлечение текста (PDF/DOCX/XLSX/PPTX, OCR сканов через vision в `pdf_ocr.py`), загрузка ссылок с SSRF-защитой и обходом страниц до 3 уровней (`LINK_CRAWL_*`). `search.py` — веб-поиск (DuckDuckGo по умолчанию без ключа, Tavily/Brave/Exa по ключу), `mcp.py` — stdio MCP-клиент («второй мозг»), `status.py` — отчёт «как дела»/«статус» (лимиты, второй мозг, живая проверка поиска с часовым лимитом), `digest.py` — ежедневное саммари каналов/групп (модель и промпт хранятся в БД), `youtube.py` — субтитры через yt-dlp. `rich.py`/`markdown.py`/`telegraph.py`/`formulas.py`/`science.py` — цепочка форматирования ответа.
- `bot/samo_helper/` — самодостаточный рабочий модуль Redmine ↔ YouGile. Не импортирует `bot.config`/`bot.bot`/БД Kapum; читает только `SAMO_HELPER_*`, ведёт отдельную синхронную SQLite (`SAMO_HELPER_DB_PATH`, абсолютный путь) и подключается через `attach_samo_helper()` до catch-all чата. Уведомления — в `SAMO_HELPER_NOTIFICATION_CHAT_ID`, напоминания — рабочему владельцу в личку; команды `/samo_*` и callbacks `samo:*` доступны только ему. `knowledge.py` — read-only поиск по саммари/ключевым словам и ссылки-источники; `llm.py` — отдельный внутренний клиент, публичные AI-хосты блокируются. Ошибка настроек отключает только модуль.
- `bot/database/` — SQLAlchemy 2.0 async: `models.py`, `repository.py`, `session.py`. Миграций через Alembic нет: `init_db()` создаёт таблицы и применяет идемпотентные `ALTER TABLE` (рабочая ветка — SQLite; PostgreSQL-ветки остались историческим заделом и не поддерживаются). Новые колонки добавлять туда же.
- `bot/config.py` — основной `Config` dataclass из env, глобальный объект `config`. Модели задаются слотами `MODEL_1..6_*` + `FALLBACK_MODEL_*` (у каждой свой URL/ключ/`VISION`); `ID` — внутренний id бота, провайдеру уходит `MODEL`. При запуске недоступные у провайдера модели скрываются из `/models`. `samo_helper` намеренно имеет отдельный `SamoHelperConfig` в `bot/samo_helper/config.py` с префиксом `SAMO_HELPER_`; не добавляйте его поля в основной Config.

Сквозные механизмы, которые видны только при чтении нескольких файлов:
- **Fallback моделей**: при ошибке/пустом ответе/превышении квоты запрос идёт следующей моделью по слотам, затем в `FALLBACK_MODEL_*` (скрыта из меню); для vision перебираются только модели с `VISION=true`.
- **Цепочка доставки ответа**: rich-сообщение (Bot API 10.1, `RICH_MESSAGES`) → MarkdownV2 → HTML → plain; таблицы/LaTeX при отказе rich → Telegraph; легаси-путь рендерит формулы в PNG / Unicode. Ошибки отправки не должны терять ответ; троттлинг ~1 сообщение/сек на чат и ретраи на 429 — в `telegram_utils.py`.
- **Вызовы инструментов**: модель должна использовать структурированное поле `tool_calls`, а не писать вызов текстом. Текстовые вызовы (JSON `name/arguments`, теги `search_notes`/`tool_call`, DSML) не исполняются и вырезаются из ответа `services/tool_markup.py:strip_tool_markup` (код в backtick-блоках не трогается); когда инструменты предложены, `TOOL_CALLS_HINT` требует штатный function calling. JSON-имитация предложенного инструмента получает один протокольный повтор на модель (для поиска — `tool_choice=search_web`), затем fallback; аргументы JSON не исполняются и не копируются в повтор. Восстановление поддержанного DSML `search_web` (`ai_client._recover_search_dsml`) выполняется до санитайзера и в обычном ответе, и в SSE.
- **Недоверенный контент** (`services/untrusted.py`): документы, страницы, цитаты/форварды и результаты поиска оборачиваются в `<untrusted_content>`; маркер сохраняется в истории, и если он есть в запросе или истории — MCP-инструменты на этот запрос не предлагаются. Новые источники внешнего текста нужно оборачивать так же. Внешний контент, кроме результатов самого поиска, отключает и `search_web`. Для нового самостоятельного чистого запроса `search.isolate_search_history` убирает из контекста всю недоверенную историю (не из БД), включая assistant-пересказы; на этот запрос разрешён только поиск, MCP/генерация/файлы остаются закрыты. Явные просьбы к заметкам маршрутизируются в `mcp.isolate_mcp_history`. Вложение/цитата в текущем запросе и обычные уточнения этот гейт не обходят.
- **Классификация запроса** (`services/request_scope.py`): общие для обоих видов изоляции правила. «Новый самостоятельный запрос» (вопрос, действие, развёрнутая просьба) отделяется от уточнения по документу (дейксис: «второй пункт», «по этой теме», «об этом» …); короткие реплики не изолируются. Здесь же маркеры интернета и второго мозга и `route()`: при обоих маркерах побеждает тот, что стоит раньше в тексте. Требования «глагол + слово интернет» больше нет.
- **Текущая дата** (`services/time_context.py`): обычный AI-чат и AI-напоминания получают текущую дату/время и вычисленное «вчера» в системном промпте; часовой пояс — глобальный `REMINDER_TIMEZONE`. Дата не сохраняется в истории.
- **Новый поиск по заметкам** (`services/mcp.py:isolate_mcp_history`): при доступном MCP новый самостоятельный запрос с явным указанием на заметки («найди во втором мозге …», «что там по проекту X в заметках?», «search my notes …») исключает всю недоверенную историю вместе с пересказами только из текущего контекста, не из БД. Отдельный глагол действия не обязателен. В обычном чате/SSE и guest остаются только read-only MCP, без веб-поиска/генерации/файлов. Вызывается перед первым раундом, но только после успешной загрузки каталога: пустой каталог/сбой сервера не вырезает историю и не запрещает веб-поиск. Текущий внешний контент и обычные уточнения гейт не обходят, результат MCP снова отключает инструменты. Отключённый MCP не включает изоляцию заметок; маршрут (`request_scope.route`) не даёт явному веб-запросу перехватить MCP-изоляцию.
- **Thinking публичных ответов** (`services/thinking.py`): `THINKING_LEVEL`/`THINKING_BUDGET` из `.env`, override владельца в `/admin → 🧠 Thinking` (`app_settings`). Поля `enable_thinking`/`reasoning_effort`/`thinking_budget` добавляет только `AIClient(..., public=True)`; intent, OCR и vision-описания референсных картинок настройку не получают.
- **MCP**: чтение всем пользователям обычного диалога (доступ/квота сохраняются); `MCP_OWNER_ONLY` больше не ограничивает чтение. Запись только `OWNER_IDS` в личке: `handlers/brain.py` (AI-intent «запомни», выбор после форварда, кнопка под ответом); `MCPManager.save_note` → `create_note(content, request_id, title, tags)` на `MCP_WRITE_SERVER` (`brain`). На сервере нужен `BRAIN_WRITE_ENABLED=true`. `services/note_metadata.py` одним AI-запросом выбранной модели (15 с, без истории/инструментов/публичного thinking) подбирает имя и ключевые теги; при сбое — локальный fallback. Сервер создаёт имя до 48 символов без `.md` (только ru/en буквы и цифры, включая уникальный суффикс), пишет YAML `tags`; retry сохраняет прежние метаданные по request_id. Нужны обновление обеих сторон и перезапуск MCP. Модель получает только `search_notes,get_chunk,get_note,list_notes`, даже при allowlist `*`; запись не доступна tool-loop. `/mcp` — только владельцу. Процесс сервера не наследует секреты бота (`_ENV_ALLOWLIST`); `command` — абсолютный путь; внешний `.mcp.json` требует пин `MCP_CONFIG_SHA256`.
- **AI-напоминания** (`services/reminders.py:_run_ai_prompt`): работают по правилам обычного вопроса — системный промпт, история чата (только чтение), дата, `search_web`. Задуманное поведение: без картинок/стикеров/MCP и без записи в историю. Каждый запуск списывает один вопрос квоты (пропуск с уведомлением, если квота исчерпана; возврат при сбое).
- **Статус** (`handlers/status.py` + `services/status.py`): «как дела»/«статус» после дешёвого префильтра подтверждает короткий AI-запрос (`request_intent.Intent.STATUS`). Отчёт показывает uptime/модель/БД, остаток квоты, счётчики второго мозга (`brain_status`, только числа) и живую проверку поиска; проверка — не чаще `STATUS_SEARCH_INTERVAL` на пользователя (атомарная запись в `status_search_checks`, переживает рестарт), при лимите выводится время следующей. Статус бесплатен для квоты, не пишет историю, в группах не показывает личные лимиты и не запускает платную проверку.
- **Публикация заметок**: ObsidianBrain после create_note выполняет commit только созданного файла и push в upstream Git-хранилища; успех — после push. Нужны write-доступ и Git identity пользователя MCP-сервера. Чужие staged-файлы/локальные коммиты не публикуются, force/merge/rebase автоматически не выполняются. При сбое файл/индекс остаются локально; повтор того же request_id повторяет push. Таймаут MCP-записи — не менее 180 секунд.
- **Разбор документов**: PDF/DOCX/XLSX/PPTX и страницы по ссылкам парсятся в отдельном пуле `docparse` под `DOCUMENT_PARSE_TIMEOUT`; `DocumentParseTimeout` → уведомление пользователя и возврат квоты.
- **Задуманное поведение — без квоты**: создание напоминаний, определение «напоминалки» в свободном тексте (`reminder_intent.py`) и определение часового пояса (`timezone_intent.py`) квоту не расходуют; квоту списывает только запуск AI-напоминания.
- **Квота**: запросы, отклонённые до обращения к модели (слишком большой файл, сбой распознавания и т.п.), квоту не расходуют; списанную квоту возвращают при сбое.
- История диалога выбирается **по чату и пользователю** (в группе контекст участников изолирован); подпись `⏱️ …` в историю не попадает. Telegraph по умолчанию выключен: его включение публикует полный ответ на публичной странице.
- `SECURITY_AUDIT.md` — результаты аудита; учитывать при правках SSRF, MCP, поиска и документов.
